Reading the map, in order

  1. 1–2Signup stays roughly what it is today — your page (or the Form) is still where a volunteer picks a shift. No change forced here.
  2. 3–4The Sheet still exists, but a script does the re-typing — this replaces the "Sundays, if I have time" step. Nothing new to learn, it just runs itself.
  3. 5Airtable becomes the one real list — instead of Form + Sheet + your memory of the rules, there's one roster everything else reads from.
  4. 6–7The text-day-before happens without you — a trigger fires the day before a shift and a texting tool sends it. This is the one new piece of software in the whole sketch.
  5. 8–9Claude checks Airtable and posts to Slack — a plain-language "who signed up for what this week" message, in the Slack you already use, every Monday. That message showing up is your signal it worked.

What's MCP?

The connector, not a new product It's what lets Claude actually reach into Airtable and Slack directly — read the roster, post the digest — instead of you copy-pasting data into a chat window. It comes with the Claude plan you already have. Box 8 on the diagram is where it lives; nothing else on the page depends on understanding it further than that.

Box 7 — picking a texting platform

Gmail and Slack can't text a phone, so box 7 needs one of these:
  • Airtable Automations + Twilio — leanest option, since Airtable already holds the roster.
  • Zapier or Make.com + a texting service (SimpleTexting, Textedly, TextMagic) — fully point-and-click, several have nonprofit pricing.
  • A volunteer-outreach platform (e.g. CallHub) — more built in, likely more than we need at our size right now.
